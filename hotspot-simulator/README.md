# AL-BARQ NET – Hotspot Simulator

مشروع Android مستقل داخل مجلد `hotspot-simulator/`، ولا يستبدل تطبيق المحفظة الموجود في جذر المستودع.

## البناء والتشغيل
1. افتح مجلد `hotspot-simulator` في Android Studio.
2. استخدم JDK 17 وAndroid SDK Platform 36.
3. نفّذ Gradle Sync ثم Build > Build APK(s)، أو شغّل `:app:assembleDebug`.
4. اختر مجلد صفحات الهوتسبوت من الهاتف. بعد الفحص، افتح المعاينة من زر مستقل.

## تجربة الاستخدام
- لوحة تحكم حديثة لا تعرض كود HTML داخل TextView.
- صفحة المعاينة تفتح في شاشة Android مستقلة مع شريط أدوات لإعادة التحميل والتشخيصات.
- المعاينة تستخدم Android WebView، مع JavaScript وDOM Storage مفعّلين.
- ملفات HTML وCSS وJavaScript والصور والخطوط تُقدّم بأنواع MIME صريحة حتى يفسر WebView الصفحة كـ HTML ويحمّل أصولها.
- دعم مجلد قالب متداخل يحتوي على `login.html`، مع حل مسارات الأصول نسبة إلى مجلد القالب.
- اعتراض نموذج الدخول المحلي قبل إرسال POST فعلي، مع ترك معالجات القالب تعمل أولاً حتى تتمكن من إكمال تحويلات الحقول المتزامنة.
- توفير أحداث `mikrotik-preview-login` و`mikrotik-preview-login-error` وواجهة `window.mikrotikPreview.requestCallback()` للقوالب ذات الانتقال أحادي الصفحة.
- محاكاة المسارات `/login` و`/status` و`/logout` وملفات RouterOS الاحتياطية مثل `flogin.html` و`fstatus.html` و`alogin.html`.
- توفير نقطة `/api` بصيغة captive-portal JSON في RouterOS، وواجهة JSON محلية مخصصة عند طلب `?var=callBack`.
- تسجيل أخطاء JavaScript وHTTP و404 وطلبات الموارد الخارجية والمتغيرات غير المدعومة في سجل التشخيصات.

## المتغيرات والشروط
تتضمن المحاكاة مجموعة شائعة من متغيرات HotSpot مثل `link-login` و`link-login-only` و`link-orig` و`link-logout` و`link-status` و`username` و`ip` و`mac` و`logged-in` و`login-by` و`uptime` و`session-time-left` وعدادات الحركة. تدعم محركات الشروط `if` و`elif` و`else` و`endif` والمقارنة `==` و`!=` والعوامل `!` و`&&` و`||` والأقواس.

## حدود المحاكاة
- القالب الموجود في `sample-hotspot/` هو fixture تجريبي فقط؛ لا يحتوي حالياً على JavaScript callback أصلي من MikroTik، وملف `js/app.js` يقتصر على تهيئة DOM وسجل console. لذلك لا يمكن استنتاج عقد callback خاص بقالب إنتاجي قبل تزويد ملفات ذلك القالب.
- نقطة `?var=callBack` عقد JSON محلي خاص بالمحاكي وليست ادعاءً بأنها callback قياسية من RouterOS. نقطة `/api` منفصلة وتحاكي صيغة captive-portal الموثقة.
- جلسة المعاينة تنتهي تلقائياً بعد 60 دقيقة. يجب إدخال اسم مستخدم؛ كلمة المرور لا تُتحقق ولا تُحفظ في وضع المحاكاة، ووجهة التحويل تُقبل فقط إذا كانت HTTP أو HTTPS.
- تسجيل الدخول محاكاة محلية تقبل اسم مستخدم غير فارغ؛ لا تتحقق من بيانات اعتماد الراوتر ولا تنشئ جلسة HotSpot حقيقية.
- لا تُنفذ مصادقة HTTP-CHAP/MD5؛ تُسجل التشخيصات تنبيهاً عند اكتشاف متغيرات CHAP.
- أوامر `on-login` و`on-logout` سكربتات RouterOS من جهة الراوتر، ولا يمكن تنفيذها داخل Android WebView. لا ينشئ التطبيق Simple Queues أو Firewall Address Lists ولا يغير إعدادات الراوتر.
- الطلبات الخارجية محجوبة في وضع المعاينة المحلي. لا توجد صلاحية INTERNET ولا خدمة رفع ملفات.

## الخصوصية والملفات
يقرأ التطبيق الملفات من URI يختاره المستخدم عبر SAF، ولا يكتب إلى مجلد المصدر. كلمة المرور لا تُخزّن ولا تُعرض في سجل التشخيص. لم تُعدّل ملفات القالب التجريبي الأصلية أثناء تحسين المحرك.

## اختبار يدوي
1. اختر مجلداً يحتوي على `login.html` ومجلدات `css` و`js` و`img`.
2. تأكد من ظهور صفحة HTML في شاشة المعاينة الجديدة مع التنسيق والتفاعلات.
3. جرّب إرسال نموذج الدخول باستخدام رقم كرت؛ الدخول الناتج محلي تجريبي فقط.
4. افتح صفحة الحالة ثم سجّل الخروج.
5. افتح التشخيصات عند غياب صورة أو ملف CSS/JS لمراجعة المسار وحالة HTTP.
