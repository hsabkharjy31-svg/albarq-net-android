# AL-BARQ NET – Hotspot Simulator

مشروع Android مستقل داخل مجلد `hotspot-simulator/`، ولا يستبدل تطبيق المحفظة الموجود في جذر المستودع.

## البناء والتشغيل
1. افتح مجلد `hotspot-simulator` في Android Studio.
2. استخدم JDK 17 وAndroid SDK Platform 36.
3. نفّذ Gradle Sync ثم Build > Build APK(s)، أو شغّل `:app:assembleDebug`.
4. اختر مجلد صفحات الهوتسبوت من الهاتف. بعد الفحص، افتح المعاينة من زر مستقل.

## تجربة الاستخدام
- لوحة تحكم حديثة لا تعرض كود HTML داخل TextView.
- صفحة المعاينة تفتح في شاشة Android مستقلة مع شريط أدوات لإعادة التحميل والتشخيصات.
- المعاينة تستخدم Android WebView، مع JavaScript وDOM Storage مفعّلين.
- ملفات HTML وCSS وJavaScript والصور والخطوط تُقدّم بأنواع MIME صريحة حتى يفسر WebView الصفحة كـ HTML ويحمّل أصولها بدلاً من عرض المصدر كنص.
- دعم مجلد قالب متداخل يحتوي على `login.html`، مع حل مسارات الأصول نسبة إلى مجلد القالب.
- تشخيص HTML بديل عند غياب الصفحة بدلاً من إظهار كود أو رسالة نصية خام.

## حدود المحاكاة
هذا التطبيق ليس RouterOS ولا يتصل بالراوتر. أوامر MikroTik التي توضع في خانات `on-login` و`on-logout` هي سكربتات تُنفذ داخل RouterOS نفسه؛ لا يمكن تشغيلها من WebView أو من Android. لذلك لا ينشئ التطبيق Simple Queues أو Firewall Address Lists، ولا ينفذ إدارة السرعة أو تحديثات الراوتر. كما أن تسجيل الدخول المعروض محاكاة محلية فقط، ولا ينشئ جلسة Hotspot حقيقية.

المحاكي يدعم مجموعة من متغيرات RouterOS وكتل الشروط الشائعة، لكنه لا يطبق CHAP/MD5 ولا يغطي جميع متغيرات وشروط RouterOS. كما لا يضمن عمل مصادر خارجية؛ الطلبات الخارجية محجوبة في وضع المعاينة المحلي.

## الخصوصية
لا توجد صلاحية INTERNET في Manifest ولا خدمة رفع. يقرأ التطبيق الملفات من URI يختاره المستخدم عبر SAF، ولا يكتب إلى مجلد المصدر. كلمة المرور لا تُخزّن ولا تُعرض في سجل التشخيص.

## اختبار يدوي
1. اختر مجلداً يحتوي على `login.html` ومجلدات `css` و`js` و`img`.
2. تأكد من ظهور صفحة HTML في شاشة المعاينة الجديدة مع التنسيق والتفاعلات.
3. جرّب إرسال نموذج الدخول باستخدام رقم كرت؛ الدخول الناتج محلي تجريبي فقط.
4. افتح التشخيصات عند غياب صورة أو ملف CSS/JS لمراجعة مسار 404.
